# 接到實際製作引擎

## 授權與能力

使用者說「做一支片」可先做前期；新增付費生成、外傳本機私有素材、公網發布與超出已授權預算必須先確認。已明確核准的範圍不反覆詢問。技能可使用網路／生成工具，不受前期驗證器的本機模式限制。

先讀正在使用的引擎文件、原生 schema 及範例，查目前供應商的模型、時長、畫幅、圖像引用方式、音訊能力及價格。能力表只作當次紀錄，不寫成故事全域鐵律。

## 交接包

交付：核准劇本、storyboard.md、project.json、資產檔案及 ID@版本表、audio-timeline.md（若有音訊）、QA／待辦、預算與執行範圍。保留來源版本與 job ID 的映射，禁止將 API key 或完整簽名下載網址寫入交接檔。

- 自用 `scene_id` / `shot_id` 先保留，再映射至引擎原生單位；單次供應商片段可包含多鏡，一個長鏡也可能需分段，不能盲目一對一。
- 角色與空間資產映射到 VisualBible 或對應的原生參考素材欄位；音訊時間映射到 Audio Master Timeline 或原生音軌。
- 提示詞文字、參考檔案引用、provider request 分開。寫下 @角色 不代表 API 真的收到圖片。

## 現有工具路由

- 使用 Hypit：先 `skill_view(name='hypit')`，按實際版本的 author/run schema 建檔，跑其原生 check/plan；沒有成功的工具輸出不得說已接通。
- 使用 CineAgent 或 media-pipeline：先確認實際工作庫、分支與未提交修改，讀該庫目前 schema／測試，不覆寫已有場景或流水線。不假設這份自用 JSON 可直接給 renderer。
- 若需要新增轉接程式，另外做測試與最小改動；本技能本身未包含已實作的 API adapter。

## 真正完成

前期通過 → 原生 plan 通過 → 授權確認 → 生成 → 下載及格式檢查 → 聽音訊／看畫面 → 核准成片。每階段報實際狀態，不將前期通過寫成影片已完成。

實際生成有失敗時保留 job ID，先查既有任務再決定重送，避免重複扣費。素材變更只重做受影響部分。
