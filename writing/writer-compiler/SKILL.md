# 我的寫手指令編譯器

將主題編譯成可重用的寫手系統指令，不把編譯和寫正文混在一起。承接自有 v3.6 的多領域、逐段詢問、多候選及大綱優先設計；輸出繁體中文。品質優先，結構服務內容。

## When to Use

- 「幫我做一個寫手」「編譯寫手 prompt」「建立自己的系列寫作指令」。
- 修改已編譯指令、續編系列、比較候選方向。
- 使用者明確要直接寫正文、改稿、劇本或分鏡：交由 `creative-production`；不要重問是否先編譯。只有意圖不明才問一次。

## 輸入與工具

先找使用者已有主題、受眾、文類、風格、篇幅、系列規劃和指令版本，只問缺的。開始時以一行狀態摘要定錨，不重複長篇背景。

Hermes 有 `clarify` 時直接使用：每輪最多三題、每題最多四個 choices；工具自帶 Other，不額外重複建立「其他」。多候選使用 `multi_select=true`。無互動工具才用繁體中文編號選單，明告降級，不假裝已呼叫工具。

## 編譯狀態流程

1. **S1A_DIRECTION**：依主題辨識領域、受眾及切入方向；另明確詢問是否需要系列／多篇規劃。使用者已明說時直接承接，不重問。系列不得靠模型擅自假定。
2. **S1B_DETAIL**：按前一步答案補一至三項真正影響指令的細節。系列優先問集數概估及全系列走向；不是固定爽文題庫。
3. **S1C_PARAMS**：補齊資訊密度、篇幅與風格；篇幅選項附字數區間。依領域為每題選一個推薦項並列在第一順位；執行模型只有使用者指定才記錄，不強制選模型。
4. **S1D_VARIANT**：依已知答案提供二至四個有實質差異的候選方向，複選一至四套。使用者明確只要一套則不再問。
5. **S1E_CONFIRM**：短摘要確認方向、細節、系列、篇幅、風格及套數；返回修改只重問受影響段。使用者明示略過確認才跳過。
6. **S2_GENERATING**：必讀 `references/writer-template.md`，逐套獨立編譯。系列嚴格先全系列大綱，再由篇章事件派生人物動機與弧線，最後補其餘模板。不得反過來讓角色牽著大綱重建。
7. **S3_DONE**：交付後可提供相關延伸方向，不強制追問。只有使用者要求執行正文，才載入 `creative-production`。
8. **S4_REVISE**：只改指定套組／部分，版本遞增，保留變更摘要。
9. **S5_SERIAL**：繼承受眾、密度、篇幅、風格；新主題直入細節。候選方向不是永久鎖定。系列延伸核查大綱與角色版本，新增篇章明示，既有角色核心動機不得默改。

使用者要求跳過提問時，以已知資料編譯，推測項放入假設說明；沒有授權不要替使用者核准素材、發布或花費。

## 自用整合邊界

- 文類為敘事時可編譯章節／beat、人物持續性及前次懸置點契約；非敘事保留資料、論據與引用規範，不注入章尾鉤子、衝突配比或角色規則。
- 系列規劃含大綱版本、人物版本、篇章 ID；單篇至少提供可追溯的大綱或文章計畫。
- 要長期執行時，另讀 `references/production-handoff.md`，在生成指令的輸入契約補上版本、前情、待回收事項。不要把專案管理 JSON 塞進文章正文。
- 不因上游提示詞禁名表而改掉使用者確認的名字。變更須提出理由、影響篇章及新版本，確認後才生效。
- 模型保持無關；使用者已指定模型才根據已查證能力適配，不使用品牌刻板策略。

## 交付與驗證

- 每套指令置於單一可複製程式碼框，首行就是寫手角色；多套附框外差異及選用說明。
- 每套包含假設說明、核心任務、輸入契約、引用規範、生成前置校準、交稿自檢；不要求揭露內部推理。
- 系列篇章覆蓋集數，人物弧線可追溯至篇章；構件 ID 與上游逐字一致。
- 自檢最多兩輪；未解決的必要缺口明列，不冒稱通過。
- 編譯出的指令保持通用 Markdown，不塞 Obsidian 語法；給使用者的使用說明筆記才依 Obsidian 規範另存。

## Pitfalls

不要把研究上游等同安裝上游。這份是自有寫手的個人適配版，原始庫不自動同步或覆寫。來源與維護範圍見 `references/provenance.md`。
